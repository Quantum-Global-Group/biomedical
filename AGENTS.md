## Cursor subagents (`Task` tool)

- The platform-only tool **`updateCurrentStep`** is **not** part of this repository. In some Cursor environments it **fails validation** when called with an **empty payload** `{}`. Background agents should **not** call it, or must pass a **non-empty** `current_step` string if the schema requires it.
- For progress tracking in subagent work on this workspace, prefer **`TodoWrite`** (or plain status text) instead of `updateCurrentStep`, so audits and implementations complete without tool errors.

## Learned User Preferences

- For the editable Next.js Visualize work, split only browser-heavy renderers (3D/D3 lifecycle) and keep synthesis helpers in `VisualizePage` rather than one monolith or a broad evidence-util refactor.
- When the workspace only has the static export, prefer shipping features as localized patches to that export instead of waiting on the missing upstream Next tree.
- For `hetqml-pages` static enhancement modules, use TDD: add failing `node --test` cases first, then implement until green.
- For HetQML Initialize parity, treat static `hetqml-pages` on port 8080 as the reference UX; `hetqml-fullstack` Next.js on port 3000 should match cascading disease → compound → gene → Hetionet metaedge with guided narrowing like that static flow.
- When auditing functional correctness per page, enumerate routes across `hetqml-pages` and `hetqml-fullstack` and record how each is verified (existing automated tests vs intentional manual checks).
- For HetQML Experiment/Visualize honesty work in `hetqml-fullstack`, align UI copy with API semantics: label simulated scaffolding (SIM) versus runner-spliced headline rows (RUN) consistently with `simulate_run`, and describe the embedding scatter as API-seeded/surrogate layout—not a learned UMAP projection—unless the backend actually implements one.
- For agent-driven installs in this monorepo, use non-interactive `pnpm install` when prompts appear (for example `CI=true pnpm install` or piping confirmation), so dependency setup does not stall waiting for a TTY.
- For HetQML demos that must support both repeatable showcases and research honesty, prefer this order: (1) copy and flow—labels and navigation match what the engine runs (including hybrid vs quantum/IBM paths and headline algorithm vs catalog) and multi-run comparison is obvious (`?jobId=` or equivalent); (2) frozen completed jobs plus a small linkable gallery; (3) runner fidelity for panels still synthetic—use env or product toggles to separate canned vs live where both need to be shown.

## Learned Workspace Facts

- `hetqml-pages/` here is a static Next.js export (serve **that** directory as the HTTP document root with `python3 -m http.server` or `npx serve`, per README), not the original editable Next.js app source; serving the repo parent or opening `file://` URLs breaks `/_next/static/*` and the UI looks unstyled. `hetqml-fullstack` runs from repo root with `pnpm install` then `pnpm dev:web`, and `pnpm dev:api` when the backend is needed; when running full and lite Next together, use different ports (for example 3000 vs `BUILD_TARGET=lite` on 3001). Root `dev:web` / `dev:api` scripts honor `HETQML_WEB_PORT` (passed as `PORT` under `apps/web`) and `HETQML_API_PORT`; if the API port is not 8000, align `API_INTERNAL_URL`, `HETQML_DEV_API_PROXY_TARGET`, and `NEXT_PUBLIC_API_URL` in `apps/web/.env.local` (FastAPI CORS allows localhost on alternate ports). If the configured API URL/port has no listening FastAPI process, the web app will fail to connect—pick free ports, update `.env.local`, and start `pnpm dev:api` with the matching `HETQML_API_PORT`.
- Git layout for preregistration work: **`main` holds the full stack**; **`roc/preregistration-tighten`** layers lite-only / static-export changes on top of updated `main` (not a mix of full and lite on `main`).
- Fly.io deploys **`hetqml-fullstack`** as **two apps** (`apps/web` + `apps/api`): Next.js uses **internal port 3000** (8080 is for static `hetqml-pages`, not the Fly web image); API uses **8000**. For the **full** web image, omit `BUILD_TARGET=lite` / `NEXT_PUBLIC_LITE_MODE`; set `NEXT_PUBLIC_*` at **Docker build** with `fly deploy --build-arg`, and use `API_INTERNAL_URL` pointing at the API’s Fly **`.internal`** host for server-side fetches (see each `fly.toml`). In deploy UIs that ask for a Fly config path, use one repo-root-relative path (e.g. `hetqml-fullstack/apps/api/fly.toml`); duplicating the `hetqml-fullstack/apps/...` prefix yields missing-file errors. For `fly deploy` from the monorepo, run with cwd inside each app package under `hetqml-fullstack` (e.g. `( cd apps/api && fly deploy )`) so Docker build context and `fly.toml` resolve correctly; deploying from the repo root with only `--config apps/.../fly.toml` can mis-resolve paths or build from the wrong `package.json` on some flyctl versions. On Fly, `/settings` can show “API offline at hydration time” when the **server** fetch via `API_INTERNAL_URL` fails (stopped/cold API, brief internal errors) even if the **browser** works via `NEXT_PUBLIC_API_URL`; that banner reflects the initial SSR attempt and does not automatically clear when later client calls succeed.
- Static `hetqml-pages` enhancements use standalone `.js` under `hetqml-pages/assets/` with one module script per page HTML and generated `_next` bundles left untouched; pages still hydrate React, so DOM tweaks may need deferred timing (e.g. `setTimeout`); exercise those modules in tests via `node --test` plus `readFile` and `import(\`data:text/javascript,${encodeURIComponent(moduleSource)}\`)` instead of a bundler.
- Related editable Next.js source for HetQML has lived outside this repo under the WSL Windows-mounted Downloads tree (not part of `biomedical/`).
- In `hetqml-fullstack/apps/web`, `ParameterCombobox` sits in a grid with cascade-locked rows using `pointer-events: none`, which can stack dropdowns under later rows and block picks; reliable mitigations include raising z-index on `.combo.open`/`.combo-list`, deferred document `mousedown` (capture) for outside close, `mousedown` on options, and forcing the open list visible in CSS when export rules would hide it.
- Root and `hetqml-fullstack/.gitignore` exclude `.cursor/`, `.claude/`, and similar dot-prefixed agent or IDE tool directories (not a blanket ignore of all hidden paths—paths like `.github/` stay tracked).
- API integration tests that use `synthetic_only` / no real `AlgoResult` splice often produce leaderboards where every row is SIM; asserting exactly one RUN requires a path that splices a real algorithm result.
- When backgrounding `pnpm dev:api` and `pnpm dev:web` from one shell command, run each with its own explicit `cd` into `hetqml-fullstack/` (for example subshells `(cd … && nohup pnpm dev:api &)` then `(cd … && nohup pnpm dev:web &)`); chaining after a bare `&` can start `dev:web` from the wrong working directory so Next never comes up as expected.
- On Initialize, the main run action stays disabled until every cascade field is filled; Playwright or smoke flows should complete all selections (or apply recommendations through the full chain) before expecting the run control to enable.
- Validate’s trust radar respects **`HETQML_TRUST_OPENTARGETS`**: default `0`/`off` keeps clinical and mechanism axes on deterministic catalog proxies (offline-safe); `1`/`on` optionally blends OpenTargets GraphQL where lookups succeed (LRU cached), document in `hetqml-fullstack/README.md` / `pipeline-status.md`.
- Each completed Initialize investigation is **one job** (`run_path.family`: `classical` | `hybrid` | `quantum`); Experiment/Validate/Visualize default to the **last** job id unless the URL carries `?jobId=…`—comparing all three families needs three runs or explicit bookmarked ids.
