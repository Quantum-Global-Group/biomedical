## Cursor subagents (`Task` tool)

- The platform-only tool **`updateCurrentStep`** is **not** part of this repository. In some Cursor environments it **fails validation** when called with an **empty payload** `{}`. Background agents should **not** call it, or must pass a **non-empty** `current_step` string if the schema requires it.
- For progress tracking in subagent work on this workspace, prefer **`TodoWrite`** (or plain status text) instead of `updateCurrentStep`, so audits and implementations complete without tool errors.

## Learned Workspace Facts

- `hetqml-pages/` here is a static Next.js export (serve **that** directory as the HTTP document root with `python3 -m http.server` or `npx serve`, per README), not the original editable Next.js app source; serving the repo parent or opening `file://` URLs breaks `/_next/static/*` and the UI looks unstyled. `hetqml-fullstack` runs from repo root with `pnpm install` then `pnpm dev:web`, and `pnpm dev:api` when the backend is needed; when running full and lite Next together, use different ports (for example 3000 vs `BUILD_TARGET=lite` on 3001). Root `dev:web` / `dev:api` scripts honor `HETQML_WEB_PORT` (passed as `PORT` under `apps/web`) and `HETQML_API_PORT`; if the API port is not 8000, align `API_INTERNAL_URL`, `HETQML_DEV_API_PROXY_TARGET`, and `NEXT_PUBLIC_API_URL` in `apps/web/.env.local` (FastAPI CORS allows localhost on alternate ports).
- Git layout for preregistration work: **`main` holds the full stack**; **`roc/preregistration-tighten`** layers lite-only / static-export changes on top of updated `main` (not a mix of full and lite on `main`).
- Fly.io deploys **`hetqml-fullstack`** as **two apps** (`apps/web` + `apps/api`): Next.js uses **internal port 3000** (8080 is for static `hetqml-pages`, not the Fly web image); API uses **8000**. For the **full** web image, omit `BUILD_TARGET=lite` / `NEXT_PUBLIC_LITE_MODE`; set `NEXT_PUBLIC_*` at **Docker build** with `fly deploy --build-arg`, and use `API_INTERNAL_URL` pointing at the API’s Fly **`.internal`** host for server-side fetches (see each `fly.toml`). In deploy UIs that ask for a Fly config path, use one repo-root-relative path (e.g. `hetqml-fullstack/apps/api/fly.toml`); duplicating the `hetqml-fullstack/apps/...` prefix yields missing-file errors. For `fly deploy` from the monorepo, run with cwd inside each app package under `hetqml-fullstack` (e.g. `( cd apps/api && fly deploy )`) so Docker build context and `fly.toml` resolve correctly; deploying from the repo root with only `--config apps/.../fly.toml` can mis-resolve paths or build from the wrong `package.json` on some flyctl versions. On Fly, `/settings` can show “API offline at hydration time” when the **server** fetch via `API_INTERNAL_URL` fails (stopped/cold API, brief internal errors) even if the **browser** works via `NEXT_PUBLIC_API_URL`; that banner reflects the initial SSR attempt and does not automatically clear when later client calls succeed.
- Enhancements target standalone `.js` modules under `hetqml-pages/assets/`, each page wires exactly one module script in its HTML, and generated `_next` bundles are left untouched.
- Those modules run in a page that still hydrates client React; DOM tweaks may need deferred timing (e.g. `setTimeout`) so selections survive React-controlled inputs.
- Node tests for the `.js` files use `node --test` plus `readFile` and `import(\`data:text/javascript,${encodeURIComponent(moduleSource)}\`)` to exercise browser-oriented ES modules without a bundler.
- Related editable Next.js source for HetQML has lived outside this repo under the WSL Windows-mounted Downloads tree (not part of `biomedical/`).
- In `hetqml-fullstack/apps/web`, `ParameterCombobox` sits in a grid with cascade-locked rows using `pointer-events: none`, which can stack dropdowns under later rows and block picks; reliable mitigations include raising z-index on `.combo.open`/`.combo-list`, deferred document `mousedown` (capture) for outside close, `mousedown` on options, and forcing the open list visible in CSS when export rules would hide it.
- Root and `hetqml-fullstack/.gitignore` exclude `.cursor/`, `.claude/`, and similar dot-prefixed agent or IDE tool directories (not a blanket ignore of all hidden paths—paths like `.github/` stay tracked).
- API integration tests that use `synthetic_only` / no real `AlgoResult` splice often produce leaderboards where every row is SIM; asserting exactly one RUN requires a path that splices a real algorithm result.
